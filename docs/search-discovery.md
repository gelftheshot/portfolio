# Search and AI discovery

The portfolio keeps its scrolling homepage and provides a permanent, statically rendered `/projects/[slug]` page for each project. Project descriptions, technical context, references, role labels, and links are ordinary readable content. Employment responsibility details remain in the initial HTML when shown in expandable sections; opening a disclosure does not fetch their text from an API. The expanded pages give both visitors and crawlers a place to inspect the work without opening a JavaScript-only dialog. `/llms-full.txt` also provides the public professional profile, employment detail, all project descriptions, and client feedback in one HTTP response.

The homepage shows three featured projects, three employment entries, and three skill areas. The remainder stays rendered inside native Read more disclosures, so closed sections retain their complete text in the initial HTML.

Client feedback is one horizontally scrollable row. Every review card is server rendered once; the motion wrapper does not clone or conditionally fetch cards. Focus, hover, manual interaction, and offscreen placement pause playback. Reduced-motion preferences start playback paused, and manual controls remain available.

## Canonical site configuration

`lib/site.js` provides `siteUrl`, `homeUrl`, `absoluteUrl(path)`, `personId`, `siteCreated`, and the `contentUpdated` date read from `profile.updatedAt` with no fallback. Next.js writes the home canonical and `og:url` as the bare origin with no trailing slash, so `homeUrl` (the bare origin) is used wherever the homepage URL is published: `og:url`, the sitemap, JSON-LD and both llms files. The default origin is `https://www.lihongebre.com`, the portfolio's adopted custom domain. The shared profile, assistant links, and résumé generator use the same configured origin. Set `NEXT_PUBLIC_SITE_URL` to the final public origin before building a deployment that uses another domain. Only HTTP or HTTPS URLs without embedded credentials are accepted; paths, query strings, and fragments are removed because the setting represents an origin. Rebuild after changing it. Never set the production canonical origin to localhost or a temporary preview host.

The root layout includes the professional title, description, self-referencing homepage canonical, author, Open Graph metadata, Twitter card, and crawl/index directives. Individual project pages supply their own titles, descriptions and canonicals. `/opengraph-image` and `/projects/[slug]/opengraph-image` produce 1200 × 630 black-and-white typographic sharing images using `next/og`; they need no remote fonts or image service, and the project images are prerendered for every slug. Neither the layout nor the project pages list `images` in their metadata, because that would override these files.

## Missing pages

`app/not-found.js` is the 404 page. It answers any unknown URL, including a project slug that is not in `data/projects.json`, because the project route sets `dynamicParams = false` and calls `notFound()`. The page has a heading, one line saying the address does not exist, and links to the home page and to the selected work. Next.js adds `<meta name="robots" content="noindex">` to every 404 response. The page sets `robots`, `alternates`, `openGraph` and `twitter` to `null`, so it inherits no canonical, `og:url` or index directive from the root layout and the injected tag is its only robots signal. While the admin is not configured, `/admin` renders this same page; see [admin-auth.md](admin-auth.md).

## Content and discovery files

- `/sitemap.xml` lists the homepage and project detail pages using canonical URLs. Redirect aliases and page fragments are excluded. The homepage `lastmod` is `profile.updatedAt`; each project uses its own `updatedAt` and falls back to `profile.updatedAt`. A URL with neither date has no `lastmod`. Admin publishing sets `profile.updatedAt`, and editing a project in the admin sets that project's `updatedAt`.
- `/robots.txt` has a `*` group and one named group per agent. The named search and user-request agents are `OAI-SearchBot`, `ChatGPT-User`, `Claude-SearchBot`, `Claude-User`, `PerplexityBot`, and `Perplexity-User`. The named crawlers are `GPTBot`, `ClaudeBot`, `Google-Extended`, `Bingbot`, `Applebot`, and `CCBot`. Every group allows `/` and disallows `/api/` and `/admin`. The disallows are repeated because a crawler that matches a named group ignores the `*` group. The file links to the canonical sitemap. The named groups state the site's intent; the `*` group already allows public pages. Robots directives are crawler instructions, not authentication or a way to publish private endpoints. Hosting, CDN, or firewall restrictions can still prevent crawling independently of this file.
- `/llms.txt` is a short Markdown index. It starts with a one-sentence definition in a blockquote: name, title, location, the span of employment years, the month of the last completed Upwork job, and the contact page. Next come the profile summary, links to the portfolio, `/llms-full.txt` and both CV files, and the `profile.updatedAt` date. The sections after that cover the common questions from `profile.faq`, employment with responsibility areas, automation focus, Upwork client work with ratings and feedback, one line per project with its role and source note, the portfolio assistant, profile links, and a few reading notes. It repeats supported descriptions rather than adding hidden claims or instructions to AI systems.
- `/llms-full.txt` is the complete public text in one Markdown response. It is generated from the shared `profile`, `projects`, and `upwork` records, plus the existing public contact email and CV links. It opens with one definitional sentence (name, title, location, years and contact URL), the CV links and the update date. The body has the summary, the homepage introduction and about text as quotations, focus areas, common questions, skill categories, expertise, automation focus, all employment descriptions and responsibility areas, education, training credentials, languages, every project's overview, source note, technical sections and references, and all completed Upwork jobs with ratings and full feedback. Featured project overviews separate role scope, the product challenge, engineering context, and evidence. Training credentials include their name, provider, dates, credential ID and link, but not the internal verification notes. A client display name is included only when the shared public record provides one. The Upwork profile figures carry the profile URL and snapshot date, rather than being presented as live statistics. The route selects public fields explicitly from the shared knowledge builder; it omits answer instructions, raw account records, contract identifiers, credentials, financial details, and private contract terms. General reading notes come last. A boundary note written for a single project sits in that project's section under "Source notes"; notes shared by several projects are left out because the reading notes cover them.
- Both text routes are `force-static` and return `Content-Type: text/markdown; charset=utf-8` with `Cache-Control: public, max-age=3600`. Two signals point readers to `/llms-full.txt`. The root layout puts `<link rel="alternate" type="text/markdown" href="/llms-full.txt">` in the homepage head. `next.config.mjs` sends a `Link: </llms-full.txt>; rel="alternate"; type="text/markdown"` header on `/`. Project pages get neither signal: they set their own `alternates` for the canonical, Next.js merges metadata shallowly, and the whole-profile file is not an alternate version of a single case study. Reading the full professional content needs no JavaScript, disclosure interaction, chat request, or second fetch. Neither text file is an established ranking factor or a substitute for HTML, links, metadata, and a sitemap.
- The homepage JSON-LD is one `@graph`. Its `Person` carries the title, summary, image, `alternateName` handles, `email`, `address`, `homeLocation`, `sameAs` links to GitHub, LinkedIn and Upwork, `knowsAbout`, one `hasCredential` entry per training record, and dated `hasOccupation` roles. The graph also has a `WebSite` and a `ProfilePage` whose `dateCreated` is `siteCreated` from `lib/site.js` and whose `dateModified` is `profile.updatedAt`. Two `ItemList` nodes follow. One lists the project case studies as `CreativeWork` items. The other lists the completed Upwork jobs; each has a `Review` with the rating and, when there is one, the written feedback. Reviews carry no `author`, because the records do not say whether a client account is a person or a company.
- Each project page has its own graph: a `CreativeWork` case study with `dateModified` from the project's `updatedAt` (else `profile.updatedAt`), an `about` node of type `SoftwareApplication`, a `citation` per reference, and a `BreadcrumbList`.
- `SoftwareSourceCode` nodes come from `sourceCodeNode()` in `components/StructuredData.jsx`. A node is emitted only for a repository in its `publicSourceRepos` list, which holds academic-advisor-ai, ai-customer-support and inventory-management-app. The homepage graph includes all three, and each of those three project pages includes its own. A project with any other GitHub link gets no `SoftwareSourceCode` node. Add a repository to the list only when it is public and holds that project's code.
- A case study is a `CreativeWork` authored for the portfolio; that does not declare sole ownership of the underlying commercial product. Project descriptions and roles must agree with the visible pages. No awards, reviews, benchmark results, or certifications are invented for structured data.
- The employment history uses the same six records in the visible homepage, assistant knowledge, `/llms.txt`, `/llms-full.txt`, and the person's dated `hasOccupation` roles. Year-only dates retain the precision supplied by Lihon for roles without a confirmed month range. ALX Africa is a Backend Developer internship from March 2023 to November 2024, confirmed by Lihon against his LinkedIn history on November 5, 2026; the visible period includes those months while structured year fields retain 2023–2024. Role names include the employer, and occupation descriptions mirror visible engineering scope; they do not infer a current employer, months or employment types for the other roles, named stacks for unspecified employers, or quantitative results. ALX Africa's existing Python, Django, REST API, and database optimization details are preserved.

Project concept images live in `public/projects/*-cover.png`, including `public/projects/seasure-cover.png` and `public/projects/projuno-cover.png`. These are concept illustrations, not live product screenshots or benchmark evidence. Academic Advisor AI, Inventory Management and AI Customer Support use application screenshots as covers (`visualType: "screenshot"`); the other projects keep concept covers, with original interface screenshots as supporting images where available. The generated social cards come from `app/opengraph-image.jsx` and `app/projects/[slug]/opengraph-image.jsx` and are not saved project images. Artwork generation prompts and source notes belong in the project artwork documentation.

## Practical limits and verification

These changes improve accessibility, link discovery, descriptive metadata, and the amount of useful project evidence available in HTML. They do not guarantee indexing, rankings, rich results, automatic reading of the optional text files, or citations in AI answers. Google states that its AI search features use the existing search requirements and do not require special AI text files or schema. Technical terminology is useful when it explains actual work; repeated keyword lists and hidden crawler-only content do not provide that evidence. The public full-text version is another representation of the same professional content available through the portfolio, not a hidden prompt for ranking or assistant behavior.

OpenAI documents `OAI-SearchBot` for search and `ChatGPT-User` for user-requested visits; the latter is not an automatic search crawler, and robots rules may not apply to those visits. Anthropic separately documents `Claude-SearchBot` for search and `Claude-User` for requested access. Perplexity similarly distinguishes `PerplexityBot` from `Perplexity-User` and says the requested fetcher generally ignores robots directives. Public-reading permission is therefore expressed consistently here without treating every agent as an indexer or assuming a robots allow rule forces access.

Before publishing, verify the production domain, project URLs, HTML descriptions and canonicals, JSON-LD, social images, sitemap, robots, the 404 page, the `Link` header, and both text responses. A single `/llms-full.txt` response should contain every role and responsibility, all project technical paragraphs and references, all completed job ratings and full feedback, the Upwork snapshot date, provided public client display names, and public contact links. It must not contain assistant system instructions or raw private account fields. After publishing, a verified site owner can use Google Search Console and Bing Webmaster Tools to inspect indexing and submit the sitemap. The monthly and quarterly checks are in [discovery-checks.md](discovery-checks.md).

## IndexNow

The IndexNow key file is `public/20d80a38995dc4949a1d36f89b71fb07.txt`. It holds only the key, and Next.js serves it from the site root as `/20d80a38995dc4949a1d36f89b71fb07.txt`. Bing and some other engines accept IndexNow; Google does not take part. Nothing in this code sends IndexNow requests. Before a manual ping after a deploy, check that the key file loads on the production origin and check the request format on indexnow.org. This implementation does not submit the site to any of these services or change their account settings.
